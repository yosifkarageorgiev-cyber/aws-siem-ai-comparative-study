# Project Logbook — Entry, 28 May 2026

## Phase 2 Round 1: First ML Run

**Activity:** Tested the implemented Isolation Forest detection layer on
two datasets (the original Phase 1 capture and a re-run Round 2 capture)
to obtain initial Phase 2 detection results.

**Outcome:** Both runs produced 0% recall on attacker windows. The
algorithm flagged 1 window in each run but neither belonged to the
known attacker IP, so both flags were false positives.

**Diagnosis:** Investigated why. Two factors identified:

- 94% of Phase 1 events (8,155 of 8,636) and ~76% of Round 2 events
  were Event ID 4703 generated by Fluent Bit itself. After filtering
  this shipper noise, both datasets resolved to a tiny number of
  feature windows (13 and 4 respectively).
- No deliberate benign baseline activity was generated in either run.
  The "normal" behaviour available for the model to learn from was
  therefore limited to background system activity from one or two
  hosts.

The Isolation Forest algorithm requires a representative population
of "normal" feature windows to draw a meaningful decision boundary.
With 11 benign windows from essentially one source in the first run,
and 2 in the second, this requirement was not met.

**Decision:** Iterate methodology rather than report this result as
the final Phase 2 finding. Plan:

1. Generate a structured benign baseline before attack execution
   (~60–90 minutes of interactive logons, file access, scheduled
   tasks).
2. Re-run the attack workload on top of the established baseline.
3. Apply the same Isolation Forest model without code changes.

**Reflection:** This iteration is itself a learning point. It
demonstrates the methodological difference between rule-based and
ML-based intrusion detection: the former needs only the attack signal,
the latter needs both the attack signal and a characterised baseline.
The first iteration is preserved as evidence in the project repository
and will be referenced in the dissertation Discussion chapter.

**Time spent:** ~3 hours (script implementation, two data captures, two
ML runs, diagnostic analysis, documentation).

**Next session:** Implement structured baseline generation script;
execute revised Phase 2 methodology.
