# Lab Architecture

This document describes the physical and logical layout of the lab
used for the project.

## Physical Setup

A single Windows 11 laptop hosts the entire lab. There is no real
cloud spend, no public network exposure, and no external dependencies
once the initial software is installed. The whole lab is reproducible
on any reasonably-specified machine (16 GB RAM or more recommended).

| Layer | Software |
|---|---|
| Hypervisor | Oracle VirtualBox |
| Container runtime | Docker Desktop for Windows |
| Shell on host | Git Bash (for bash scripts) and PowerShell (for the baseline generator) |

## Logical Topology

The entire lab uses a single private host-only VirtualBox network
`192.168.56.0/24`. This network is isolated from the public internet
by design; the VMs cannot reach the outside world and the outside
world cannot reach them.

## Data Flow

For each event, the path through the lab is:

1. An action (attack or baseline activity) occurs against the Windows
   Server.
2. The Windows Security audit policy records the action as a Security
   Event Log entry (4624, 4625, 4672, etc.).
3. Fluent Bit's `winlog` input plugin polls the Security/Application/
   System channels every 1 second and reads new entries.
4. Fluent Bit's `opensearch` output plugin POSTs each event as a JSON
   document to `http://192.168.56.1:9200/winlogbeat/_doc`.
5. OpenSearch indexes the document and makes it queryable.
6. Two consumers read from the index:
   - OpenSearch Dashboards reads on demand to populate the visualisations (Phase 1 rule-based detection).
   - The Anomaly Detection plugin reads continuously to score new events (Phase 2 ML-enhanced detection).
7. A SOC analyst views the dashboard; both rule-based and ML-based findings appear as panels and alerts.

## Why This Setup

The architecture was chosen for three reasons:

1. **Realism**. The OpenSearch + Fluent Bit + Windows Event Log
   pipeline is a real production pattern. The same architecture is
   used in many small and mid-size organisations.
2. **Reproducibility**. The whole lab is described in a docker-compose
   file plus two VM appliances. Anyone can rebuild it on their own
   hardware in a few hours.
3. **Cost**. Running the lab is free. LocalStack stands in for AWS
   services without any actual AWS account or charges.

## Limitations of the Setup

Three limitations of this lab worth noting:

1. **One host runs everything**. Under load (Docker + 2 VMs + browser)
   the host can hit resource pressure that causes VMs to freeze.
   Mitigated by closing other apps before runs.
2. **One target machine**. The dataset's source-IP diversity is
   inherently low. A multi-machine target would produce a richer
   dataset more suited to ML detection.
3. **Self-noise from Fluent Bit**. Event 4703 (token right adjusted),
   generated by Fluent Bit's own service process, accounted for 94%
   of Phase 1 events. A production configuration would exclude this
   activity at the shipper.
